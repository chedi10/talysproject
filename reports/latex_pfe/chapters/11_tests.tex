\section{Stratégie de test}

La validation du prototype combine :
\begin{itemize}[leftmargin=*]
  \item tests \textbf{unitaires} implicites (scripts d'entraînement, smoke tests) ;
  \item tests \textbf{d'intégration API} (Postman, PowerShell, Swagger) ;
  \item tests \textbf{fonctionnels} bout-en-bout (React + API + Ollama) ;
  \item revue \textbf{métier} (checklist REF-08).
\end{itemize}

\section{Validation frontend}

Checklist manuelle React :
\begin{enumerate}[leftmargin=*]
  \item Logo Talys visible en header ;
  \item Switch Explain / Chat fonctionnel ;
  \item KPI colorés (vert/ambre/rouge) selon risque ;
  \item Tableau crédits pour CIN multi-crédits (88710263) ;
  \item Badges intent/path/cin après chat ;
  \item Sources RAG affichées avec score \% ;
  \item Téléchargement PDF avec logo.

Build production : \texttt{npm run build} — succès sans erreur TypeScript.

\section{Limites des tests}

\begin{itemize}[leftmargin=*]
  \item Pas de suite pytest automatisée complète ;
  \item Pas de tests de charge (locust) ;
  \item Pas de validation A/B avec analystes réels ;
  \item Métriques ML sur données synthétiques optimistes.
\end{itemize}

\section{Retour d'expérience}

\begin{itemize}[leftmargin=*]
  \item \textbf{Points forts} : architecture modulaire, démo bout-en-bout convaincante, alignement REF-08 ;
  \item \textbf{Difficultés} : timeouts Ollama, encodage PDF Unicode, pickling index RAG ;
  \item \textbf{Leçons} : séparer scoring et LLM dès la conception ; curer le corpus RAG ; prévoir fallbacks.
\end{itemize}
